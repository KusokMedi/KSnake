# KSnake

Классическая игра «Змейка» для десктопа, написанная на C++17 с использованием SDL2 и SDL2_ttf.

Скачать игру можно в [Releases](https://github.com/KusokMedi/KSnake/releases).

Читать на [English](README.md).

## Возможности

- Поле 20×15 с адаптивным размером окна
- Окно можно менять, но не меньше 400×360: меньшие размеры не вмещают вёрстку
  (минимум применяется на первом кадре и работает на всех бэкендах, включая Wayland)
- Плавное движение змейки: отрисовка интерполируется между шагами по сетке, поэтому змейка
  скользит, а не прыгает на целую клетку за тик (правила остаются поклеточными)
- Управление с клавиатуры и мыши (выбор кнопок в меню, кликабельные кнопки на экранах)
- Пауза по `Esc`, продолжение по `Space`, повторный `Esc` — выход в меню
- Экран Game Over с результатами (New Score, Time, Best); заполнение всего поля
  завершает партию надписью `You Won!`
- Сохранение лучшего счёта в подписанный JSON
- Проверка обновлений по релизам GitHub: в фоне при запуске (не чаще одного раза в 8 часов,
  результат хранится между запусками) и вручную из главного меню
- Пункт меню `Check for updates` становится жёлтым, если вышло обновление
- Интерфейс масштабируется вместе с окном, но не крупнее базовой вёрстки: в фуллскрине
  он не раздувается, а уменьшается (до нижней границы) только у совсем маленьких окон
- Фон — статичная картинка на весь экран, привязанная к центру экрана (в центре экрана
  центр клетки); окно лишь показывает свою часть, поэтому узор не «уезжает» при изменении
  размера окна с любого угла. На сессиях Wayland игра идёт через X11 (XWayland), если он
  доступен, так как SDL не сообщает позицию окна на native Wayland. Без XWayland или при
  заданном `SDL_VIDEODRIVER` используется бэкенд по умолчанию
- Приложение представляется как `KSnake`: имя процесса (видно в системных мониторах) и
  X11 `WM_CLASS`/app id равны `KSnake`, а окно показывает иконку игры. В AppImage кладётся
  подходящий `.desktop` (`StartupWMClass=KSnake`), а Windows-`.exe` несёт иконку и
  `VERSIONINFO`, поэтому Task Manager показывает имя и описание
- Поддержка фуллскрина (F11)
- Кросс-платформенность: Linux и Windows
- Сборочный скрипт, собирающий релизные артефакты: AppImage и однофайловый Windows `.exe`
- Иконка приложения вшита в оба артефакта (исходник — `assets/ksnake.svg`)

## Управление

| Действие | Клавиши |
|---|---|
| Движение | Стрелки |
| Пауза | `Esc` |
| Продолжить из паузы | `Space` |
| В меню (из паузы / Game Over) | `Esc` |
| Рестарт после Game Over | `Space` (или `R`) |
| Фуллскрин | `F11` |

На паузе и на Game Over есть кликабельные кнопки `Continue` / `Restart` и `Menu`,
поэтому оба экрана полностью управляются мышью.
Остальные подсказки (`Enter to exit`, `Any key to return` и т.д.) тоже кликабельны:
наводишь — подсвечивается, кликаешь — выполняется это действие.

В главном меню можно управляться стрелками и `Enter`, а также мышью. Пункты меню доступны и по цифрам `1`-`6`.
`Skins` и `Settings` — заглушки, сейчас показывают `Coming soon..`.

## Требования

- CMake 3.10 или новее
- Компилятор с C++17 (GCC/Clang в Linux, MinGW-w64 или MSVC в Windows)
- Библиотеки разработки SDL2 и SDL2_ttf
  - Linux: `pkg-config` и пакеты `sdl2` и `sdl2_ttf`
  - Windows: заголовки и библиотеки SDL2/SDL2_ttf, которые находит CMake
- Для релизной сборки под Windows (кросс-компиляция из Linux) дополнительно нужны
  `x86_64-w64-mingw32-g++`, `x86_64-w64-mingw32-windres`, `curl` и `unzip`; пакеты
  разработки SDL2/SDL2_ttf для MinGW скачиваются в `.release-cache/` автоматически

## Сборка и запуск

```bash
./build.sh          # настройка и сборка в build/ (по умолчанию Release)
./start.sh          # собрать при необходимости и запустить build/snake с --debug в stdout
./fresh-start.sh    # удалить build/, собрать заново и запустить
```

`build.sh` принимает переменную окружения `BUILD_DIR`; остальные скрипты тоже её используют.

## Сборка релизных артефактов

```bash
./build_release.sh [VERSION]
```

Аргумент версии по умолчанию берётся из файла [`VERSION`](VERSION). Локальные артефакты
складываются в `final_build/<VERSION>/`:

- `KSnake-<VERSION>-x86_64.AppImage`
- `KSnake-<VERSION>-windows-x86_64.exe` — самодостаточный: игра, обе DLL SDL2,
  шрифт и `VERSION` вшиты как ресурсы Windows

Скрипт только собирает файлы локально. Публикация релиза (git-теги, загрузка) — отдельный
ручной шаг, и скрипт его не выполняет.

## Пересборка иконки

```bash
./assets/make_icons.sh
```

Пересобирает PNG-набор (16, 24, 32, 48, 64, 128, 256, 512) и `assets/ksnake.ico`
из `assets/ksnake.svg`. Нужны `rsvg-convert` (librsvg) и ImageMagick (`magick` или
`convert`). Уже закоммиченные файлы в `assets/` релизная сборка использует как есть;
пересобирать их нужно только после правки SVG.

## Структура

```
KSnake/
├── src/                 # исходники игры, по файлу на подсистему
│   ├── main.cpp         # точка сборки: инициализация SDL, ввод, главный цикл
│   ├── config.h         # константы поля/окна, минимальный размер, пути к шрифтам
│   ├── game.h/.cpp      # логика змейки: поле, повороты, шаг, столкновения (без SDL)
│   ├── ui.h/.cpp        # шрифты, масштаб UI, layout, примитивы отрисовки, кэш текста
│   ├── screens.h/.cpp   # экраны: меню, поле, пауза, game over, credits, обновления
│   ├── update.h/.cpp    # проверка обновлений: кэш, фоновый поток, GitHub API
│   ├── storage.h/.cpp   # каталог пользователя, scores.json
│   ├── version.h/.cpp   # чтение файла VERSION
│   └── util.h/.cpp      # строки, разбор/сравнение версий, запуск процессов
├── VERSION              # текущая версия, единственный источник истины
├── assets/
│   ├── font.ttf         # шрифт
│   ├── ksnake.svg       # исходник иконки
│   ├── ksnake-*.png     # отрендеренные размеры иконки 16-512
│   ├── ksnake.ico       # иконка для Windows
│   └── make_icons.sh    # пересборка PNG/ICO из ksnake.svg
├── third_party/
│   ├── nlohmann/json.hpp        # вендоренный заголовок JSON
│   └── win_singlefile/singlefile.cpp  # лаунчер однофайлового exe для Windows
├── tests/               # юнит-тесты, headless-прогоны, фаззеры, визуальная оснастка
├── docs/TESTING.md      # как запускать тестовую оснастку
├── build.sh             # сборка для разработки
├── build_release.sh     # релизная сборка (AppImage + Windows exe)
├── start.sh             # запуск
├── fresh-start.sh       # удалить build/, собрать заново и запустить
└── CMakeLists.txt       # конфигурация сборки
```

## Версия

Текущая версия лежит в файле [`VERSION`](VERSION) в корне репозитория.
Игра читает его при запуске из папки рядом с бинарником, а `build_release.sh` использует
его как тег релиза по умолчанию — чтобы выпустить новую версию, достаточно поменять одно число.
